# 自审检查点清单

`SKILL.md` 里那份是够用的精简版，这份是展开版。两个场景用得上：

1. 想让 AI 审得更深，把这份一起喂给它
2. 自己当 Reviewer 时当对照表用

---

## ① 边界条件

### 输入值

- [ ] `null` / `undefined` / `None` / 空指针
- [ ] 空字符串、纯空格字符串
- [ ] 空数组 / 空对象 / 空 Map
- [ ] `0`、负数、`-1`
- [ ] 极大值 / 极小值（溢出、`Number.MAX_SAFE_INTEGER`）
- [ ] 浮点精度（`0.1 + 0.2`、金额计算用没用整数分）
- [ ] 超长输入（字符串长度、数组长度有没有上限）
- [ ] 特殊字符、Unicode、emoji（数据库字段长度按字符还是字节算）
- [ ] 类型不符（前端传字符串 "123"，后端当数字用）

### 集合与索引

- [ ] 数组首尾元素、单元素数组
- [ ] `arr[0]` 在数组为空时、`arr[arr.length]` 越界
- [ ] 分页：offset 超过总数、size 为 0 或负数、最后一页
- [ ] 去重 / 排序在空集合上的行为

### 时间与状态

- [ ] 时区（存储 UTC、展示本地？前端传的是带时区还是不带？）
- [ ] 跨天、跨月、跨年的边界（「今天」的起止怎么算）
- [ ] 闰年、月末（1 月 31 日 + 1 个月 = ？）
- [ ] 日期区间查询：闭区间还是开区间，边界值算不算
- [ ] 状态机：非法状态流转有没有拦住

### 并发与时序

- [ ] 并发下重复提交（幂等做了吗）
- [ ] 竞态：读-改-写之间数据被别人改了
- [ ] 异步没 `await`、Promise  rejection 没处理
- [ ] 回调被调用两次、监听器重复注册

---

## ② 异常处理

### 捕获与吞掉

- [ ] 空的 `catch {}` / `except: pass`
- [ ] `catch (e) { console.log(e) }` 然后继续执行——吞得不够干净
- [ ] `catch` 范围过宽（整个函数包在一个 try 里，分不清哪步失败）
- [ ] 用异常做正常流程控制（性能 + 可读性都差）

### 资源释放

- [ ] 文件句柄、数据库连接、事务没关
- [ ] 锁没释放（尤其在异常路径上）
- [ ] 定时器、`setInterval` 没清理
- [ ] 事件监听器没解绑（组件卸载、长生命周期对象）
- [ ] 有没有用 `try/finally` 或语言自带的 `using` / `defer` / `with`

### 一致性与恢复

- [ ] 多步操作失败后，前面已完成的步骤回滚了吗
- [ ] 中间态会不会被别的请求读到
- [ ] 重试是否幂等（重复执行结果一样吗）
- [ ] 重试有没有退避、有没有次数上限（会不会重试风暴）
- [ ] 外部调用超时设了吗（默认值是不是太长）

### 错误信息

- [ ] 堆栈、SQL 语句、内部路径直接返回给前端
- [ ] 返回的错误信息用户看不懂，或者反过来泄露了内部实现
- [ ] 日志记了足够定位问题的上下文吗（请求 id、关键参数）
- [ ] 有没有把用户的原始输入原样打进日志（日志注入）

---

## ③ 性能瓶颈

### IO

- [ ] 循环里查数据库 / 发 HTTP 请求 / 读写文件（N+1）
- [ ] 能不能批量化（一次 `WHERE id IN (...)` 代替 N 次查询）
- [ ] 数据库查询走索引了吗（`WHERE` 条件、排序字段）
- [ ] 查了整行但只用了两个字段（能不能 `SELECT` 指定列）
- [ ] 串行等待能否并行（`Promise.all`、并发请求）

### 计算与内存

- [ ] 嵌套循环，复杂度能不能降
- [ ] 大数组全量遍历 / 全量拷贝，能不能流式处理
- [ ] 循环里做重复计算（能不能提到循环外）
- [ ] 递归深度有没有上限（栈溢出）

### 增长失控

- [ ] 缓存不淘汰、没有容量上限
- [ ] 数组 / Map 只增不删
- [ ] 日志文件不打滚
- [ ] 分页接口一次性返回全部数据（没有分页或分页失效）
- [ ] 大对象被闭包 / 全局变量 / 监听器意外持有，无法回收

### 前端专项

- [ ] 大列表没有虚拟滚动
- [ ] 频繁触发的事件没防抖 / 节流（`scroll`、`input`、`resize`）
- [ ] 渲染循环里创建新对象导致不必要的重渲染

---

## ④ 安全风险

### 注入

- [ ] SQL 拼接（有没有用参数化查询 / 预编译）
- [ ] 命令注入（用户输入进了 `exec` / `child_process`）
- [ ] XSS（用户输入直接用 `innerHTML`、模板没转义）
- [ ] 路径穿越（文件名里有 `../`）
- [ ] 模板注入、反序列化漏洞

### 越权

- [ ] 只校验了「登录没登录」，没校验「这条数据是不是他的」（水平越权）
- [ ] 只校验了前端隐藏按钮，后端没校验角色（垂直越权）
- [ ] 直接信任前端传来的用户 id / 价格 / 数量，后端不重新算
- [ ] 接口暴露了不该暴露的字段（密码哈希、内部备注）

### 敏感信息

- [ ] 密码、token、密钥、身份证、手机号进了日志
- [ ] 密钥硬编码在代码里（应该走环境变量 / 配置中心）
- [ ] 错误信息返回了敏感数据
- [ ] 传输是否加密、日志是否脱敏

### 其他

- [ ] 上传文件：类型、大小、存储路径有没有限制；会不会覆盖已有文件
- [ ] 依赖有没有已知漏洞（`npm audit` / `pip-audit`）
- [ ] CSRF / SSRF（后端是否会去请求用户提供的 URL）
- [ ] 限流：登录、短信、支付等接口有没有频率限制
- [ ] 随机数用于安全场景时用了不安全的随机源

---

## 一句话心法

对每一处代码问：**「什么输入、什么时序下它会出错？」**

而不是「它写得优不优雅」。后者是品味问题，前者才是 Reviewer 的活。
